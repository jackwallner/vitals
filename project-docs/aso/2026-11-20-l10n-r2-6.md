# Localization ASO upgrade, round 2 batch r2-6, 2026-11-20

Locales: or-IN, pa-IN, ta-IN, te-IN, ur-PK. Nothing was pushed to App Store Connect; edits are in `fastlane/metadata/<locale>/` (name, subtitle, keywords, promotional_text, description). Method as in round 1 (`2026-11-20-l10n.md`): Apple MZSearchHints per storefront, iTunes Search API for ranks and competitors, Apple's indexing table (https://developer.apple.com/help/app-store-connect/reference/app-store-localizations).

## Evidence quality: thin for all five

- Apple's table: India (IND) indexes en-GB as primary and Bangla, Gujarati, Hindi, Kannada, Malayalam, Marathi, Odia, Punjabi, Tamil, Telugu and Urdu as secondary. Pakistan (PAK) indexes en-GB and Urdu. So or-IN, pa-IN, ta-IN and te-IN are each indexed only in India, and ur-PK in Pakistan and India. en-US is not indexed in either country, so en-US keyword words are not covered there; only the en-GB field is (`tdee,counter,calculator,apple,burned,bmr,deficit,resting,active,pedometer,steps,ring,bmi,intake,move`, name `Total Calories - Daily Tracker`, subtitle `Kcal Burn on Watch & Widget`).
- Autocomplete (IN 143467, PK 143477, with language variants `-1` to `-17`): no suggestion exists for any native-script calorie, step or pedometer seed in Odia, Punjabi, Tamil, Telugu or Urdu (`କ୍ୟାଲୋରୀ`, `ਕੈਲੋਰੀ`, `கலோரி`, `கலோரிகள்`, `అడుగులు`, `కేలరీలు`, `کیلوری`, `قدم`, `پیڈومیٹر` and more all return empty). Bare consonant seeds do return native suggestions (Tamil `க` -> தமிழ் காலண்டர்; Telugu `క` -> తెలుగు క్యాలెండర్; Punjabi `ਸ` -> ਜਪੁਜੀ ਸਾਹਿਬ), so the endpoint works for these scripts: there is just no health-app demand surfaced. Odia returned nothing for any seed.
- The iTunes Search API returns 0 results for any native-script term in IN or PK, so the exact-name collision check (brief: ASC refuses a name equal to another app's) cannot be run for these five names. No other app was found, but that is absence of a testable index, not proof. If ASC refuses one, add a short suffix word.
- English demand in IN and PK (same for all five): `calorie` -> calorie tracker, calorie counter, calorie calculator; `calories burned` -> calories burned activity app / calculator; `step counter` -> step counter & walking tracker, step counter pedometer app; `tdee` -> tdee calculator; `pedometer` -> pedometer step counter. All of that is English and is already carried by the en-GB field. Competitors for `calories burned` in IN: Calories Burned Calculator +, Calories Burnt Calculator Log, Calories Sport & Activity; for `calorie counter`: MyFitnessPal (33k ratings), Healthify (66k), Lose It!, Cal AI.
- Our rank (iTunes API, IN): `daily calorie burn` 2, `calorie widget` 16, `calories burned` 25, `apple watch calories` 26, `tdee` not in top 50. PK: `daily calorie burn` 28; `calories burned`, `tdee`, `calorie widget`, `apple watch calories` not in top 50.
- Approach: since there is no native demand data, the fields use the plainest native word for each concept (calories, burn, steps, walk, exercise, health, weight, rest, active, deficit, energy, pedometer, Apple, watch, widget, lock screen), with both common spellings of the calorie word split between name/subtitle and keywords where the script has two (Odia କ୍ୟାଲୋରି / କ୍ୟାଲୋରୀ, Telugu కేలరీలు / క్యాలరీలు, Punjabi ਕੈਲੋਰੀ / ਕੈਲੋਰੀਆਂ), plus loanwords people type in native script (`ஸ்டெப்ஸ்`, `స్టెప్స్`, `ਸਟੈੱਪ`, `ଷ୍ଟେପ୍ସ` for steps). Those words are not in the en-GB field, so they add coverage for India. Every locale is marked thin evidence.
- Naming (Jack's flag list): no food-logger head term (calorie counter) exists in any of these five names. All five lead with the burn phrase, so each is a burn-over-head-term choice. Because there is no local head term autocomplete at all, the real cost is nil; the English head terms stay in en-GB.
- Keyword budget note: Indic scripts use many code points per word. The 100-character limit is counted as characters by `scripts/check-locale-fields.py` and `scripts/validate-aso-metadata.py` (bytes shown by the validator are higher, as for every existing locale).
